How this works

What you are looking at

Every row is one translation unit — a single string Weglot serves on the live site. The left column is the English source, the right column is what visitors in this language see today. All of it is machine translation.

The four decisions

  • Approve — the current text is fine. Nothing is sent to Weglot; approving simply records that a human has read it.
  • Edit — type the wording you want. Your text wins over everything else.
  • Flag — something is wrong but you do not want to fix it now. Flagged rows stay easy to find.
  • Re-translate — add the row to the queue for a fresh machine draft. The button then reads Queued and stops responding; take it back out from Review queue.

Why Re-translate does not do anything immediately

It adds the row to a queue and nothing more. Clicking it repeatedly cannot start five jobs or spend five times — a row is either in the queue or it is not, and clicking again only ever adds, so a stray double-click cannot quietly undo itself either. Removing is done from Review queue, where you can see what you are removing. The queue is sent as one batch, and only after a separate confirmation that shows you how many rows and roughly what it costs.

Your decisions are kept in this browser

They apply instantly and survive a reload. Saving them back to the repository, and sending the queue, are not wired up yet — the desk is being built before the machine translation is connected, so the review flow can be judged first.

Keyboard

J / K move between rows, A approves, F flags, R queues, E edits, Esc closes this box.
